Build Phase 1 of a responsive web application called AGAPAY.

AGAPAY is a conversational healthcare navigation platform designed for patients in the Philippines.

The patient should NOT experience AGAPAY as a traditional healthcare management application with many menus, tabs, forms, and dashboards.

Instead, the main patient experience is a conversational AI assistant called ARAMON.

CORE PRODUCT PRINCIPLE:

"Don't make patients learn the system. Let the system understand the patient."

The user should be able to simply tell ARAMON what they need in natural language, and the application should respond with helpful conversational responses and contextual action cards.

This is PHASE 1 ONLY.

Do not build the clinic dashboard, doctor dashboard, EHR management, real appointment backend, QR scanning system, payment system, or LGU dashboard yet.

Phase 1 should focus on creating a polished, highly usable patient-facing conversational experience that can later be expanded into those features.

==================================================
2. PRIMARY TARGET USER
==================================================

Design primarily for:

- Senior citizens
- Adults with low digital literacy
- Patients who are uncomfortable with complicated applications
- Patients who prefer conversational interaction
- Filipino users
- Users who may prefer Filipino rather than English

The interface must therefore prioritize:

- Simplicity
- Large text
- Large buttons
- Large touch targets
- Clear language
- High contrast
- Minimal navigation
- Voice interaction
- Visual confirmation
- Very low cognitive load

The application must NOT feel childish.

It should feel like a modern, premium healthcare product that happens to be extremely easy to use.
